# NIRN.Ai — Set Up an Exact Copy on a New Machine

This is the one file to read to get this project running from a zip. Follow
it top to bottom in order — most setup failures are just a step done out of
order (e.g. seeding before Postgres is running).

## 0. Before you zip / unzip — read this first

This project has an **AI vector search index that is ~6.4 GB and is not
tracked in git** (`backend/data/index.faiss` + `backend/data/chunks.pkl`).
Without it, search, draft generation, and conflict detection will not work.
**These two files cannot be quickly regenerated** — see the note in Step 6 —
so the single most important thing to get right is making sure they survive
the transfer to your friend's machine.

There is also `backend/data/index.faiss.flat.bak` (9 GB) — the original,
uncompressed version of the same index, kept here as your own backup from
when it was compressed down to the current `index.faiss`. The running app
never reads it (only `index.faiss` is used), so it does **not** need to go
in the transfer to your friend — just don't delete your own copy of it.
`backend/data/metadata.txt` (115 MB) is likewise unused by the running app
and can be left out too.

**Also exclude these before zipping** — they're all regenerated by the setup
steps below and just bloat the archive:
- `venv/` (Python virtual environment)
- `frontend/node_modules/`
- `backend/__pycache__/`, and any other `__pycache__/` folders
- `backend/data/nirn_store.db` (local chat-session cache, regenerates itself)

So the two files that actually matter for the transfer are:
- `backend/data/index.faiss` (~2.3 GB)
- `backend/data/chunks.pkl` (~4.1 GB)

~6.4 GB total is too big for most email attachments but fits fine on a USB
drive, an external SSD, or a shared Google Drive/WeTransfer link — use
whichever of those is easiest, separately from (or alongside) the rest of
the zip.

## 1. Prerequisites to install

Install these first, in this order:

| Tool | Version used here | Get it |
|---|---|---|
| Python | 3.14.x (3.11+ should also work) | https://www.python.org/downloads/ |
| Node.js | v22.x | https://nodejs.org (LTS or current) |
| PostgreSQL | 18.x | macOS: `brew install postgresql@18` · Windows/Linux: https://www.postgresql.org/download/ |
| Ollama | latest | https://ollama.com/download |
| git | any recent version | usually already installed |

After installing Ollama, pull the model this project uses:
```bash
ollama pull gemma3:4b
```

## 2. Unzip and confirm the data files are present

```bash
cd "NIRN 2 dont"          # or whatever the unzipped folder is named
ls -la backend/data/       # must show index.faiss and chunks.pkl, several GB each
```
If those two files are missing, get them from whoever sent you this project
(see **Step 0**) before continuing — **Step 6** explains why rebuilding them
yourself isn't a realistic shortcut.

## 3. Backend: Python environment

```bash
cd "NIRN 2 dont"
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. PostgreSQL: create the database and app role

Start Postgres if it isn't already running:
```bash
# macOS (Homebrew)
brew services start postgresql@18
```

Find your Postgres **superuser role name** — on a fresh Homebrew install
this is usually your OS username, NOT `postgres`:
```bash
psql postgres -c "\du"
```

Run the provisioning script (idempotent — safe to re-run), replacing
`YOUR_SUPERUSER_NAME` and choosing your own app password:
```bash
cd backend
PGSUPERUSER=YOUR_SUPERUSER_NAME NIRN_APP_PASSWORD='choose-a-password' ./scripts/setup_local_db.sh
```
This creates the `nirn_ai` database and a restricted `nirn_app` role that
only has SELECT/INSERT/UPDATE/DELETE — no schema-modifying privileges.

## 5. Configure environment variables

```bash
cd ..                            # back to the project root
cp .env.example .env
```
Edit `.env`:
- `DATABASE_URL` — set the password to match `NIRN_APP_PASSWORD` from Step 4.
- `ALEMBIC_DATABASE_URL` — set the user to your Postgres superuser role name
  from Step 4 (this is the sync connection Alembic uses to run migrations —
  it needs DDL privileges, `nirn_app` does not have them).
- `JWT_SECRET` — generate a fresh one, don't reuse this repo's:
  ```bash
  python3 -c "import secrets; print(secrets.token_urlsafe(48))"
  ```
- Leave `LLM_PROVIDER`, `OLLAMA_MODEL`, `OLLAMA_BASE_URL` as-is if Ollama is
  running locally on the default port.

Now apply the database schema and seed the starter accounts:
```bash
cd backend
source ../venv/bin/activate      # if not already active
alembic upgrade head
python3 seed.py
```
`seed.py` prints the seeded login credentials when it finishes — save that
output. If you don't have it, the defaults are:

| Login ID | Password | Role |
|---|---|---|
| `admin` | `NirnAdmin#2026` | Admin |
| `priya.sharma` | `Officer#Pass01` | Officer |
| `rahul.deshmukh` | `Officer#Pass02` | Officer |

Both officer accounts are forced to change their password on first login.

## 6. If `backend/data/index.faiss` / `chunks.pkl` didn't make it across

There is no quick local script for this — the scripts that exist in this
repo (`backend/gr_assistant/build_faiss.py`, `backend/build_ivfpq.py`,
`backend/build_ivfsq.py`) are one-off migration tools from this project's
own history, not a repeatable "build from scratch" pipeline, and the first
one is explicitly marked deprecated in its own header. The actual from-
scratch build is `kaggle/build_gr_index.ipynb`, which re-embeds the entire
~2.9M-chunk `mahGRs` corpus — a substantial data-science job (GPU strongly
recommended), not a one-command fix.

**Strongly prefer transferring the two files directly** (Step 0) over
rebuilding. Only go down the notebook route if that's genuinely not an
option.

## 7. Frontend

```bash
cd frontend
npm install
```

## 8. Run it

You need three things running at once, each in its own terminal:

```bash
# Terminal 1 — Ollama (skip if it's already running as a background service)
ollama serve

# Terminal 2 — backend (from the project root, with venv active)
cd backend
uvicorn app:app --reload

# Terminal 3 — frontend
cd frontend
npm run dev
```

Open **http://localhost:3000**. The frontend dev server proxies `/api` and
`/health` to the backend on port 8000 automatically — no extra config.

## 9. Verify it actually works

- Log in as `admin` / `NirnAdmin#2026`.
- Go to Draft GR, generate a draft — this calls Ollama, so the first
  generation can take 30–60s depending on the machine.
- Check the Policy Conflicts tab populates after generation.
- Try Search from the home page and confirm results come back (this is
  what proves `index.faiss`/`chunks.pkl` loaded correctly).
- Download the generated draft as PDF and DOCX and confirm both open and
  read correctly.

## Troubleshooting

**`ModuleNotFoundError: No module named 'psycopg2'` when running `alembic upgrade head`**
Alembic needs the sync Postgres driver even though the app itself uses the
async one. It's in `requirements.txt` (`psycopg2-binary`) — if you skipped
`pip install -r requirements.txt` or installed into the wrong environment,
run it again with the venv active.

**Login returns 500, or `alembic`/`seed.py` fail with a role/connection error**
Almost always means Postgres isn't running, or `ALEMBIC_DATABASE_URL` in
`.env` has the wrong superuser role name. Re-check Step 4.

**Search returns no results / draft generation says the corpus is empty**
`backend/data/index.faiss` and `chunks.pkl` are missing or in the wrong
place. Re-check Step 2 — see Step 6 for why you want to get these files
transferred rather than regenerated.

**Draft generation hangs or times out**
Ollama isn't running, or `gemma3:4b` wasn't pulled. Run `ollama list` to
check which models you have.

**Port already in use (3000 or 8000)**
Something else on your machine is already using it. Either stop that
process, or change the port — backend: `uvicorn app:app --reload --port 8001`
and update the proxy target in `frontend/vite.config.js`; frontend:
`vite.config.js`'s `server.port`.
